# Linuxネットワーク障害の切り分け手順

## 目的

Ubuntuでネットワーク通信ができない場合に、問題が発生している箇所を段階的に調査するための備忘録。

## 1. 基本的な切り分け手順

| 順番 | 確認項目 | コマンド | 確認できること |
|---|---|---|---|
| 1 | ループバック | `ping -c 4 127.0.0.1` | OS内部のICMP通信 |
| 2 | IPアドレス・IF状態 | `ip -br addr` | IPアドレスの割り当て、IFの状態 |
| 3 | ルーティング | `ip route` | デフォルトゲートウェイと経路 |
| 4 | ゲートウェイ | `ping -c 4 <ゲートウェイIP>` | ゲートウェイへのICMP通信 |
| 5 | 外部IPアドレス | `ping -c 4 1.1.1.1` | 外部へのICMP通信 |
| 6 | DNS名前解決 | `resolvectl query example.com` | ドメイン名の名前解決 |
| 7 | Web通信 | `curl -I https://example.com` | HTTPSによる応答の確認 |

※ pingが失敗しても、ICMP応答が制限されている可能性があるため、通信障害と断定しない。

## 2. コマンドの詳細

### 2.1 ループバックの確認

```bash
ping -c 4 127.0.0.1
```

- 成功：OS内部のループバック通信が動作している
- 失敗：ループバック設定やOS内部のネットワーク機能を調査

物理LANや外部ネットワークの正常性は確認できない。

### 2.2 IPアドレスとインターフェースの確認

```bash
ip -br addr
```

確認項目：

- インターフェース名
- 動作状態（UP、DOWNなど）
- 割り当てられたIPアドレス

### 2.3 ルーティングの確認

```bash
ip route
```

表示例：

```text
default via 10.0.2.2 dev enp0s3
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15
```

主な意味：

- `default`：他に適合する経路がない場合に使用
- `via`：次に通信を渡すゲートウェイ
- `dev`：使用するネットワークインターフェース
- `src`：優先される送信元IPアドレス

特定の宛先への経路確認：

```bash
ip route get 1.1.1.1
```

### 2.4 ゲートウェイへの通信確認

```bash
ping -c 4 10.0.2.2
```

※ 10.0.2.2はVirtualBox NAT環境の一般的な例。実際には `ip route` で確認したアドレスを使用する。

### 2.5 外部ネットワークへの通信確認

```bash
ping -c 4 1.1.1.1
```

- 成功：外部IPアドレスとのICMP通信が可能
- 失敗：経路、NAT、ファイアウォール、ICMP制限などを調査

### 2.6 DNS名前解決の確認

```bash
resolvectl query example.com
```

IPアドレスへの通信は成功するのに名前解決だけ失敗する場合、DNS設定やDNSサーバーへの通信を調査する。

DNS設定確認：

```bash
resolvectl status
```

### 2.7 Web通信の確認

```bash
curl -I https://example.com
```

HTTPSで接続し、HTTPレスポンスヘッダーを取得する。

DNS、TCP接続、TLS、HTTPなどの動作確認に利用できる。

## 3. 障害切り分けの考え方

| 現象 | 主に疑う箇所 |
|---|---|
| ループバックに失敗 | OS内部のネットワーク設定 |
| IPアドレスがない | DHCP・ネットワーク設定 |
| デフォルト経路がない | ルーティング設定 |
| ゲートウェイに応答がない | 仮想ネットワーク・経路・ICMP制限 |
| 外部IPへの通信に失敗 | NAT・ルーティング・外部通信制限 |
| 名前解決だけ失敗 | DNS関連 |
| DNS成功、HTTPS失敗 | TCP・TLS・Webサービス・通信制限 |

※ これらは原因候補であり、追加調査によって特定する。

## 4. 学習時の注意点

- 最初は設定変更をせず、現在の状態を確認する
- エラーメッセージとコマンドの実行結果を記録する
- 1つの検査結果だけで原因を断定しない
- 設定変更する場合は元に戻せるようにする

本資料はネットワーク障害対応時の確認手順を整理した備忘録であり、すべての項目を実環境で検証済みという意味ではない。
